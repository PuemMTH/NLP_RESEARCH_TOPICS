3 — Current vs. Upgraded Evaluation Metrics (Module 2)
Module 2 — NOW
WER (newmm tokenizer) Cosine Similarity (generic SentenceTransformer)
Tokenizer drift problem: Thai WER differs significantly by tokenizer. The same OCR output scores 13.6% WER with newmm vs 8.2% WER with deepcut — a ~40% relative difference on the same underlying text. Comparisons across systems are invalid unless all use the identical tokenizer version. This is currently uncontrolled in Module 2.
Cosine similarity via generic multilingual SentenceTransformer is not calibrated for Thai medical/product domain. A wrong medical term can show high cosine similarity if it appears in similar embedding context.
Module 2 — UPGRADED (3-Layer Stack)
L1: CER (character error rate) L2: ANLS* (edit-distance tolerant) L3: LLM-as-Judge (Typhoon2-Text)
Why CER over WER: CER is tokenizer-independent — counts character edits, eliminating the newmm drift entirely. ANLS* (arXiv 2402.03848) tolerates minor Thai OCR character confusions while penalizing semantically wrong answers. LLM-judge catches domain errors where cosine similarity fails (e.g., similar embeddings for different medical terms).
Additional upgrade: replace generic cosine sim with BERTScore using WangchanBERTa (already in Stage 4 post-correction — reuse at zero infrastructure cost). Effort: 1 day (Idea 4A).

5 — Ideas Detail
Idea 1 — Module 1 Upgrade
VLM Zero-Shot Classifier (replaces 700-char threshold)
Use Typhoon2-Vision or Qwen2.5-VL-7B with a contrastive prompt to classify ad images vs. product labels. Zero-shot — no labelled training data required. Fallback to text-length threshold when VLM confidence < 0.7. Model: scb10x/typhoon2-qwen2vl-7b-vision-instruct
1–2 days
Idea 2 — Module 2 Upgrade (Priority 1)
3-Layer Evaluation Stack: CER + ANLS* + LLM-Judge
L1: CER via jiwer/fastwer (tokenizer-independent). L2: ANLS* via PyPI anls package (edit-distance tolerant). L3: LLM-as-Judge with Typhoon2-Text (domain-aware, rate-limited to samples where L1/L2 disagree). Eliminates the ~40% relative WER drift from newmm tokenizer.
2–3 days
Idea 3 — Pipeline Architecture
VLM as Unified Stage 3+4+5 POC
Typhoon OCR V1.5 (2B) or Qwen2.5-VL as single-pass: image in → structured JSON/Markdown out. Eliminates inter-stage error accumulation. Trade-off: ~4–6 GB vs ~930 MB for modular pipeline. Recommended as hybrid fallback when Stage 4 ANLS score < 0.6.
3–5 days
Idea 4A — Module 2 Upgrade (Priority 3)
BERTScore with WangchanBERTa
Replace generic cosine similarity with token-level BERTScore using WangchanBERTa as encoder. WangchanBERTa is already in the Stage 4 pipeline — reuse at zero infrastructure cost. In-domain encoder outperforms generic cosine similarity for Thai medical/product text.
1 day
Idea 4C — Module 1 Signal
CLIP Image-Text Alignment as OCR Quality Signal
Use CLIP or SigLIP to score alignment between product image and extracted OCR text. Low score = OCR text doesn't match image content = likely extraction error. Acts as automatic OCR quality signal without ground truth. Note: Standard CLIP has limited Thai text understanding; prefer Typhoon2-Vision.
2 days
Idea 5 — Infrastructure
Internal ThaiOCRBench Evaluation Framework
Adapt ThaiOCRBench methodology (2,808 samples, 13 task categories) to the NECTEC product/medical domain. Collect 200–500 images: product labels, prescription forms, lab results, government ID sections. Annotate with ground-truth text + key-value fields. Run all pipeline variants. Score with 3-layer stack.
2–3 weeks
Idea 6 — Long-Term / Publishable
LoRA Fine-Tune Typhoon OCR for Thai Medical Domain
Fine-tune Typhoon OCR V1.5 (2B) with LoRA on 100–300 annotated Thai medical documents. Evaluate with field-level F1 and term-preservation rate. Risk: medical annotation requires clinical review — start with pharmacy-grade product labels. Evidence: Low-resource VLM survey (ScienceDirect 2026) validates instruction tuning on synthetic data.
4–6 weeks

7 — Publication Gaps & Research Opportunities
Thai CLIP Gap
No publicly available CLIP model fine-tuned on Thai product-image + Thai text pairs. Standard CLIP (ViT-L/14) has limited Thai text understanding. Building this would be a publishable contribution and directly unblock Idea 4C and Idea 7 (multimodal Module 1 overhaul).
CER vs WER Tokenizer Variance for OCR (not ASR)
Existing Thai WER tokenizer variance studies (arXiv 2208.04799) are from the ASR domain. No paper specifically compares CER and WER as OCR metrics for Thai, accounting for character complexity (vowel stacking above/below/left/right of base consonant, tone marks). A short study would fill this gap and directly improve Module 2.
Typhoon OCR on SME Product Labels
Typhoon OCR benchmarks cover financial reports, government forms, books, and infographics. Performance on SME product labels (messy layouts, multilingual text, varied fonts, handwritten additions) is completely unknown. Direct evaluation would produce novel benchmark results.
ANLS Behavior on Thai Vowel Stacking
ANLS* threshold (0.5) was tuned for Latin-script DocVQA tasks. Thai vowel stacking means a single character edit can change word meaning drastically. Whether the 0.5 threshold is appropriate for Thai OCR evaluation has not been studied.
Constrained LLM-Judge for Thai Medical OCR
Using an unconstrained LLM judge risks hallucinating medical term corrections. A constrained judge (with lexicon lock, similar to Stage 4 post-correction) has not been published for Thai medical OCR. This is a safety-critical gap if Idea 2 (L3 LLM-judge) is deployed in production.
