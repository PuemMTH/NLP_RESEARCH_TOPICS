Research Summary · 2026-05-06

ต่อยอดงาน NLP ที่ NECTEC ไปเป็นหัวข้อ LLM/VLM

สรุปนี้เชื่อมงานเดิมด้านการทำความสะอาดข้อมูลสินค้า SME และการวัดผล OCR เข้ากับแนววิจัย LLM/VLM ที่ทำได้จริง โดยยังคงใช้ PyThaiNLP, WER, SentenceTransformer และ cosine similarity เป็น baseline หลัก

ฐานงานเดิม

SME Data Cleaning

Product Name Cleaning & Classification

  • ตัดคำภาษาไทยด้วย PyThaiNLP word_tokenize engine newmm
  • ใช้ regex คัดกรองภาษาไทย อังกฤษ และตัวเลข
  • ตัดสัญลักษณ์พิเศษและ emoji ด้วย dictionary/set
  • นับ word frequency และตัดคำที่พบน้อยกว่า threshold
  • ใช้ text length threshold 700 อักขระเพื่อแยกรูปที่มีข้อความเยอะ
OCR Evaluation

Thai OCR Metrics

  • คำนวณ WER หลังตัดคำภาษาไทยด้วย PyThaiNLP
  • ใช้ SentenceTransformer สร้าง text embedding
  • ใช้ cosine similarity วัดความใกล้เคียงเชิงความหมาย
  • เหมาะสำหรับต่อเป็น reliability metric ที่ละเอียดกว่า exact string match

หัวข้อที่แนะนำที่สุด

Reliability-Aware Evaluation and Correction of Thai OCR Outputs using Deterministic Metrics, Sentence Embeddings, and LLM-as-a-Judge

หัวข้อนี้ต่อจากงานเดิมตรงที่สุด เพราะไม่ต้องทิ้ง WER หรือ semantic similarity แต่เพิ่ม LLM เป็น evaluator อีกชั้นหนึ่งเพื่อวัดว่า OCR output ใช้งานจริงได้หรือไม่

ส่วนประกอบ บทบาท เหตุผล
PyThaiNLP + WER/CER Deterministic baseline ทำซ้ำได้ อธิบายง่าย เหมาะกับภาษาไทยที่ต้องตัดคำก่อนวัด WER
SentenceTransformer Semantic baseline วัดความหมายที่ใกล้กัน แม้ข้อความไม่ตรงตัวอักษรแบบเป๊ะ
LLM-as-a-Judge Reliability layer ให้คะแนน readability, meaning preservation, numeric/unit preservation และ hallucination risk
Constrained correction Post-OCR improvement ให้ LLM แก้ข้อความโดยล็อก entity สำคัญ เช่น brand, number, unit, medical/product term

ทางเลือกวิจัยที่ต่อยอดได้

Direction 1

LLM-Assisted Thai Product Name Normalization

เทียบ regex/PyThaiNLP cleaning กับ LLM ที่ normalize ชื่อสินค้าโดยต้องรักษา brand, quantity, unit และชื่อเฉพาะ

Direction 2

LLM-as-a-Judge for Thai OCR Evaluation

เพิ่ม judge score ข้าง WER และ cosine similarity เพื่อประเมินว่า OCR output ยังสื่อความหมายถูกและใช้ได้จริงไหม

Direction 3

VLM-Based Text-Heavy Image Classification

แทน threshold 700 อักขระด้วย VLM หรือ OCR+classifier เพื่อแยกรูปสินค้าออกจากภาพโฆษณา/ป้ายข้อความ

Direction 4

Thai OCR Post-Correction With Constrained LLMs

ใช้ LLM แก้ OCR แต่ป้องกัน over-correction ด้วย protected spans สำหรับตัวเลข หน่วย brand และคำเฉพาะทาง

สรุปหัวข้อ Research ที่เพิ่มมา

ส่วนนี้สรุปจากไฟล์ research/ideas/ideas-vlm-thai-ocr-extension-2026-05.md โดยเน้นว่าแต่ละหัวข้อช่วยต่อยอด module เดิมตรงไหน และควรใช้เป็น POC หรือ thesis direction แบบใด

1. Replace 700-Char Heuristic with VLM Zero-Shot Classifier Effort: 1-2 days

ใช้ VLM เช่น Typhoon2-Vision หรือ Qwen2.5-VL แทน threshold 700 อักขระ เพื่อแยกภาพ product label/packaging ออกจากภาพโฆษณา วิธีนี้ลดความเปราะของ rule เดิม และเริ่มได้แบบ zero-shot โดยยังใช้ threshold เดิมเป็น fallback เมื่อ confidence ต่ำ

2. Upgrade OCR Evaluation to CER + ANLS + LLM-Judge Effort: 2-3 days

ปรับ Module 2 จาก WER + cosine similarity เป็น 3-layer evaluation stack: CER สำหรับลดปัญหา tokenizer bias ในภาษาไทย, ANLS สำหรับ tolerance ต่อ OCR typo, และ LLM-as-a-Judge สำหรับตรวจ semantic correctness เช่น medical term, number และ unit หัวข้อนี้ควรทำก่อนสุดเพราะ effort ต่ำแต่ impact สูง

3. VLM as Unified Stage 3+4+5 Effort: 3-5 days

ใช้ Typhoon OCR หรือ Qwen2.5-VL ทำ OCR, correction และ structured extraction ใน pass เดียว แทน pipeline แยก Stage 3 → Stage 4 → Stage 5 ข้อดีคือเข้าใจ layout ได้ดีกว่าและลด error accumulation แต่กิน memory/latency มากกว่า modular pipeline จึงเหมาะเป็น fallback เมื่อ confidence ต่ำ

4. VLM/LLM for Semantic OCR Evaluation Effort: 1-2 days

อัปเกรด semantic similarity จาก SentenceTransformer cosine similarity ไปเป็น BERTScore ด้วย WangchanBERTa หรือใช้ Typhoon2-Text เป็น LLM judge สำหรับ domain-specific correctness อีกทางคือใช้ CLIP/SigLIP วัด image-text alignment ในงานสินค้า SME

5. ThaiOCRBench as Internal Evaluation Framework Effort: 2-3 weeks

สร้าง benchmark ภายในสำหรับ product labels, prescription forms, lab results และเอกสารไทยอื่น ๆ โดย annotate ground truth text และ key-value fields แล้วรันเทียบ OCR-only, OCR+correction, WangchanBERTa/ByT5 และ VLM-unified หัวข้อนี้ดีมากสำหรับงานระยะกลางเพราะใช้วัด regression ได้

6. Low-Resource Fine-Tuning of Typhoon OCR for Medical Domain Effort: 4-6 weeks

Fine-tune Typhoon OCR ด้วย LoRA บนเอกสารการแพทย์ไทย 100-300 หน้า เพื่อให้จับ medical layout และ vocabulary ได้ดีขึ้น เหมาะเป็นหัวข้อ publishable แต่มีความเสี่ยงเรื่อง annotation และ clinical review จึงควรเริ่มจาก product/pharmacy label ก่อน

7. Multimodal Product Data Cleaning Effort: 3 days-3 weeks

ยกเครื่อง Module 1 จาก text-only pipeline เป็น image+text representation โดยใช้ CLIP, BLIP-2 หรือ VLM ไทยเพื่อวัดว่า OCR text สอดคล้องกับภาพสินค้าจริงไหม ใช้ได้ทั้ง data quality checking, product classification และ product deduplication

เพิ่มใหม่: LLM as a Verifier

งาน verifier ต่อจาก LLM-as-a-Judge โดยตรง แต่เปลี่ยนคำถามจาก “output นี้ดีแค่ไหน” เป็น “field หรือ claim นี้มีหลักฐานรองรับจริงไหม” จึงเหมาะกับ OCR มากกว่า generic judge score โดยเฉพาะเอกสารที่มีตัวเลข หน่วย วันที่ ชื่อยา ชื่อสินค้า และ key-value fields

แนวทาง Output ใช้กับงานเดิมยังไง
LLM-as-a-Judge score, ranking, explanation ใช้เสริม WER/CER/cosine similarity เพื่อประเมินคุณภาพ OCR โดยรวม
LLM-as-a-Verifier supported, unsupported, uncertain + evidence span ตรวจว่า field ที่ OCR/extractor สร้างขึ้นมีหลักฐานจาก OCR line, bbox, image crop หรือ reference text จริงไหม
Evidence-grounded verifier label + reason + severity เหมาะกับ critical fields เช่น dosage, lab value, unit, brand, quantity และ product name

Verifier Pipeline ที่ควรเพิ่ม

Claim / Field Decomposition

แยก OCR output หรือ extracted JSON เป็น field ย่อย เช่น product name, brand, quantity, unit, test name, value, date

Evidence Retrieval

ดึงหลักฐานจาก OCR line, bbox, image crop, product dictionary, medical lexicon หรือ reference text

LLM Verification

ให้ verifier ตรวจทีละ field และคืน supported, unsupported หรือ uncertain พร้อมเหตุผลสั้น ๆ

Safety Action

field ที่ unsupported หรือ uncertain ต้อง fallback ไป rule check, VLM re-read, หรือ human review โดยเฉพาะ field ความเสี่ยงสูง

Internal Thai Product/Medical OCRBench Priority 1

Cost-Aware OCR Evaluation Cascade Priority 2

วาง evaluation เป็นชั้น: exact/rule/CER → ANLS/BERTScore → LLM judge/verifier โดยเรียก LLM เฉพาะกรณี metric ขัดแย้ง, confidence ต่ำ หรือ field มี criticality สูง

Typhoon OCR vs Qwen2.5-VL vs Modular Pipeline Baseline Study

เปรียบเทียบ modular pipeline เดิมกับ Thai-specific VLM และ general VLM ด้วย metric เดียวกัน: CER, key-value F1, ANLS, verifier false-pass rate, latency และ VRAM

Thai Product Image-Text Alignment Gap Updated

gap ที่ถูกต้องไม่ใช่ “ไม่มี Thai CLIP” แต่คือ public Thai/multilingual image-text models ยังไม่ถูก validate กับ noisy SME product-label OCR โดยตรง ควรทดสอบ Thai-light multimodal, Jina CLIP v2 และ Typhoon2-Vision

Evidence-Grounded VLM Fallback Deployment Design

ไม่ควรใช้ VLM-only ตั้งแต่ต้น ให้ modular OCR เป็น default แล้วใช้ verifier/router เรียก VLM เฉพาะ field หรือ region ที่ unsupported, uncertain, low-confidence หรือ layout ซับซ้อน
