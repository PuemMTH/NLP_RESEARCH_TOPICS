Ideas: NECTEC NLP Work → LLM/VLM Extensions (2026-05)

Context From Prior Work

Prior NECTEC work has two useful NLP foundations:

  • SME product data cleaning and classification: Thai word tokenization with PyThaiNLP newmm, regex language filtering, symbol/emoji cleanup, word frequency thresholding, and text-length heuristics for image-type separation.
  • OCR evaluation: Thai-tokenized WER using PyThaiNLP and semantic similarity using SentenceTransformer embeddings plus cosine similarity.

This is a strong base for research because it already has practical data noise, Thai-language preprocessing, image/text coupling, and evaluation metrics.

Best LLM/VLM Extension Directions

1. LLM-Assisted Thai Product Name Normalization

Core idea: compare rule-based/PyThaiNLP cleaning against LLM-assisted normalization for noisy SME product names.

Research question:

  • Can a Thai-capable LLM normalize SME product names better than dictionary + regex + frequency filtering while preserving brand, quantity, unit, and product-specific terms?

Possible method:

  • Baseline A: existing PyThaiNLP + regex + word-frequency filtering.
  • Baseline B: SentenceTransformer clustering + nearest canonical product name.
  • Proposed: LLM generates normalized product name with constraints: preserve brand, preserve numbers/units, remove promotional words, remove emoji/symbol noise.

Metrics:

  • Exact match to manually normalized names.
  • Token-level F1 after Thai tokenization.
  • Brand/number/unit preservation rate.
  • Human preference score for product search quality.

2. LLM-as-a-Judge for Thai OCR Evaluation

Core idea: extend WER and cosine similarity with an LLM judge that scores whether OCR output is acceptable for downstream use.

Research question:

  • Can LLM-as-a-Judge better capture Thai OCR usability than WER and embedding cosine similarity alone?

Possible method:

  • Input: reference text, OCR hypothesis, optional image crop.
  • Output: structured scores for readability, semantic preservation, numeric preservation, unit preservation, and hallucination risk.
  • Compare judge scores with human annotations.

Important caveat:

  • LLM judge should not replace deterministic metrics. Use it as an additional semantic/reliability layer because LLM judging can be prompt-sensitive and less reproducible.

3. VLM-Based Text-Heavy Image Classification for SME Products

Core idea: replace the fixed 700-character threshold with a learned or VLM-assisted classifier.

Research question:

  • Can a VLM classify SME product images into "product photo" vs "text-heavy advertisement/claim label" more robustly than OCR text-length thresholding?

Possible method:

  • Baseline A: existing OCR text length threshold.
  • Baseline B: OCR + classical classifier using text length, keyword density, and bounding-box coverage.
  • Proposed: VLM prompt or fine-tuned lightweight classifier using image + OCR text.

Metrics:

  • Image-type classification F1.
  • False rejection rate for valid product images.
  • Error breakdown by packaging text, promotional poster, ingredient label, and certificate image.

4. Thai OCR Post-Correction With Constrained LLMs

Core idea: use the existing OCR evaluation work as a benchmark for post-correction, not only metric reporting.

Research question:

  • Can an LLM correct Thai OCR output while preserving critical entities such as product names, brands, numbers, units, and medical/product terms?

Possible method:

  • Baseline A: raw OCR.
  • Baseline B: ByT5 or WangchanBERTa correction.
  • Proposed: constrained LLM correction with protected spans for numbers, units, named entities, and dictionary terms.

Metrics:

  • CER/WER.
  • Semantic similarity.
  • Protected-span preservation rate.
  • Over-correction rate.

Recommended Thesis/Research Angle

Best risk-adjusted direction:

"Reliability-Aware Evaluation and Correction of Thai OCR Outputs using Deterministic Metrics, Sentence Embeddings, and LLM-as-a-Judge"

Why this fits:

  • Directly extends prior NECTEC OCR evaluation work.
  • Does not require collecting a huge dataset first.
  • Keeps PyThaiNLP and SentenceTransformer as strong baselines.
  • Adds an LLM contribution without making the whole system dependent on an LLM.
  • Can be tested on both SME product text and Thai medical/OCR documents already represented in this workspace.

First POC Candidate

Create poc/llm-ocr-evaluator/:

  • Input: reference.txt, hypothesis.txt, optional OCR detection JSON.
  • Compute: Thai-tokenized WER, CER, SentenceTransformer cosine similarity.
  • Add: LLM judge prompt that returns JSON scores.
  • Output: one evaluation report JSON plus a Markdown summary.

This POC can reuse prior logic and become the bridge from classical NLP evaluation to LLM-based reliability evaluation.
